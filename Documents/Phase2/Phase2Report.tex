\section{Report}
\subsection{Approach}
	\begin{itemize} [itemsep=0pt]
	\item We used agile-style development with short iterations to allow incremental building and adjustment as problems arose.
	\item implemented libGDX as our backbone library.
	\item Features were developed in small modules (player movement, enemies, scoring, deliveries) and then integrated into the main game.
	\item Team roles were split into Design, Front End, and Back End.
	\item We maintained meetings at least once per week where we coordinated, tested, and collaborated. This approach worked well with our short iteration-style development.
	\end{itemize}
\subsection{Modifications from Phase 1}
	\begin{itemize}[itemsep=0pt]
    \item We originally planned for a dog police, but we ended up changing it to a human.
    \item Unlock the next part of the map with fish instead of deliveries.
    \item All point actions (Fishes, Deliveries, Enemy collision deductions) all translate to a single displayed ‘Fish’ score, instead of all being separate counters.
    \item Because we decided to use the libGDX framework after our initial planning  stage, the structure of our code is completely different:
    \begin{itemize}[topsep=2pt]
    \item libGDX helped us cut down the number of classes/code needed. For example:
    	\begin{itemize}
    	\item The import, "import com.badlogic.gdx.graphics.OrthographicCamera" is libGDX’s built-in camera class, making it easier for us to use the code for the camera movement
		\item Built in render(), show(), dispose(), etc. methods
    	\end{itemize}
    
	\item We have separate classes for separate game screens, which we did not anticipate that we needed
    \end{itemize}

	\end{itemize}

\subsection{Team Management}

	\begin{itemize}
    \item Assigned clear roles (front end, back end, design) that changed throughout the project based on circumstance and completion
    \item Divided tasks in each role based on the order of requirements so work could support other group members
    \item Ensured everyone always had something to work on
    \item Held weekly meetings to check progress

\subsection{External Libraries}
For this project we used the external library: \textbf{libGDX}
\begin{itemize}
\item It is used in many well-known games.
\item It is a widely used library with strong community support and documentation.
\item It is versatile and relatively easy to implement and use.
\item It provides the tools needed to handle our game’s graphics, input, and overall functionality.
\end{itemize}
