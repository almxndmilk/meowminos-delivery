\section{Smell 1 --- Duplicated Code (\texttt{CatOffBike.java}, lines 128--136, commit \texttt{cb26430e})}

\subsection*{Description}
The animation-advance block in \texttt{walkToward()} is a verbatim copy of the same block in \texttt{update()}:
\begin{lstlisting}[language=Java]
if (lastDirection != prevDirection) { currentFrameIndex = 0; animTimer = 0f; }
animTimer += delta;
if (animTimer >= FRAME_DURATION) {
    int frameCount = (...LEFT || ...RIGHT) ? 2 : 3;
    currentFrameIndex = (currentFrameIndex + 1) % frameCount;
}
prevDirection = lastDirection;  updateFrame();
\end{lstlisting}

\subsection*{Analysis}
Lecture week10-2 slide 3: \textit{``if you see the same code structure in more than one place, your program will be better if you find a way to unify them.''} Also \textbf{Copy and Paste Programming} (week10-1 slide 5). If the logic changes, both copies must be updated; missing one causes silent inconsistency.

\subsection*{Refactoring}
Extracted \texttt{private void advanceAnimation(float delta)} and called it from both methods.

\section{Smell 2 --- Dead Code (\texttt{ObamaScreen.java}, lines 380--384, commit \texttt{bb6e1e5b})}

\subsection*{Description}
An \texttt{if}-block sets \texttt{totalDuration} to the same value it was just assigned:
\begin{lstlisting}[language=Java]
float totalDuration = TALK_FALLBACK_DURATION;      // set here
if (SettingsScreen.soundOn && obamaVoice != null) {
    totalDuration = TALK_FALLBACK_DURATION;        // identical -- no-op
}
\end{lstlisting}

\subsection*{Analysis}
A4 brief lists \textit{dead code} as a smell. The branch is a complete no-op and never changes state. The comment promises ``prefer actual audio duration'' but never delivers, misleading the reader.

\subsection*{Refactoring}
Deleted lines 381--384 entirely; \texttt{totalDuration} is already correct on the line above.

\section{Smell 3 --- Per-Frame Allocation in Render Loop (\texttt{ObamaScreen.java}, line 377, commit \texttt{bb6e1e5b})}

\subsection*{Description}
\texttt{getProgressiveDialogue()} is called every render frame and re-splits the \texttt{static final} constant \texttt{DIALOGUE} every time:
\begin{lstlisting}[language=Java]
String[] words = DIALOGUE.split(" ");  // new array allocated every frame
\end{lstlisting}

\subsection*{Analysis}
\texttt{DIALOGUE} never changes, so allocating a new \texttt{String[]} 60 times per second adds unnecessary GC pressure. The project coding conventions state \textit{``avoid per-frame allocations in render loops.''} Lecture week10-1 slide 6 (\textit{Spaghetti Code}) flags unstructured code that ignores obvious improvements.

\subsection*{Refactoring}
Hoisted to a class-level constant: \texttt{private static final String[] DIALOGUE\_WORDS = DIALOGUE.split(" ");} and updated \texttt{getProgressiveDialogue()} to use it.

\section{Smell 4 --- Magic Numbers / Primitive Obsession (\texttt{ObamaScreen.java}, lines 126--136, 287, commit \texttt{fc31eb21})}

\subsection*{Description}
Raw coordinate literals scattered across the constructor and \texttt{updateObamaWalk()}. \texttt{810f} appears in both with no shared constant:
\begin{lstlisting}[language=Java]
float doorBottomY = map3YOffset + map3Height - 810f;  // constructor line 127
this.obamaTargetY = map3YOffset + map3Height - 885f;
this.camStartY    = map3YOffset + map3Height - 910f;
// line 287 in updateObamaWalk():
... (map3YOffset + map3Height - 810f) ...             // silent duplicate
\end{lstlisting}

\subsection*{Analysis}
Lecture week10-2 slide 10 (\textit{Primitive Obsession}): \textit{``don't be reluctant to use small objects for small tasks.''} A4 brief lists \textit{``unjustified use of primitives.''} Without names, \texttt{810f} is meaningless. The duplicated \texttt{810f} at line 287 is easy to miss, leaving Obama walking to the wrong position.

\subsection*{Refactoring}
Extracted \texttt{DOOR\_IMG\_Y = 810f}, \texttt{TARGET\_IMG\_Y = 885f}, \texttt{CAM\_START\_IMG\_Y = 910f}, \texttt{CAM\_END\_IMG\_Y = 790f}, \texttt{DOOR\_IMG\_X = 1407f}, \texttt{TARGET\_IMG\_X = 1400f} as named constants. All six occurrences now reference these.
